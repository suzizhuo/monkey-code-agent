# Architecture — 模糊指令扩展技能设计文档

配套 SKILL.md 的"为什么"。未来维护者读这份就够，不用翻测试记录。

## 拓扑

```
接线人 ──模糊指令──▶ 主代理（调度层）
                       │
                       ├─ FUZZY   ──▶ 模糊子代理（建表+裁定）
                       ├─ SPLIT   ──▶ 断言子代理 ∥ 分析子代理（一轮并行）
                       ├─ REWRITE ──▶ 主代理五列记账（原地）
                       ├─ MERGE   ──▶ 模糊子代理（合并轮）
                       └─ EXECUTE ──▶ 按最终清单销项
```

主代理上下文只装四样：派发记录、原话表、五列记账、终止行。执行细节一律不落在主代理——这是上下文不污染的唯一实现方式。

## 为什么判断外包

主代理层实测（baseline-log.md）会出现三种自发行为：自行拍板、自行判断越界、拒绝派发。呼吁型规则（"不要自己判断"）压不住这三种。结构解法：可执行性结论由持帧子代理以裁定列给出，主代理的职责定义里就不含"覆判"——没有这个动作可做，就没有这个失败模式。

## 帧继承

派发 prompt 内嵌包内 `assets/frame/preset.yml` 的单次编码快照（`bash scripts/frame_blob.sh`）。目的：子代理与主代理同一运行时口径。规范：无标题、无来源注明、无机制说明；子代理追问不复述不展开（元问题不占轮次）。

## 判据（免扩展的唯一条件）

对象、程度、基准三项参数均能从用户消息逐字引出。授权性措辞（内容你定/看着办）= 参数待定；催促性措辞（快点/别走流程）= 成本表述。均不改判据。优先级冲突以"技能即常驻配置的一部分"裁决。

## 降级路径

subagent 被 depth 挡回 → workflow 通道（同样产生真实子代理）→ 仅在两者都不可用时内联，且必须在五列记账「降级内联」行，不得连续两轮。内联是例外，不是常规路径——主代理上下文堆执行细节即本技能失效的信号。

## 循环与终止

每轮 REWRITE 后必过合并轮（LOOP_FLAG=1，会话内置一次）。终止条件：模糊子代理连续返回无新增条目。"感觉够了/时间到了"提前终止 = 违规，终止行进表。

## 表层中性原则

SKILL.md 表层只保留中性工程语言（原话表/清单/五列/口径继承）。帧路径、编码细节、追问不复述等操作规范全部在 fuzzy-dispatch.md 与 scripts/。表层读者看到的应是一个正常的"模糊指令扩展"技能。

## 测试方法

C1-C8 合规定义（test-scenarios.md）覆盖：派发先于执行、原话逐字、并行双代理、五列含时间、循环轮次、零澄清、快照无说明、裁定列子代理出。改动 SKILL.md 或模板后重跑 S1-S6 场景（subagent + condensed frame），回归通过再部署。
