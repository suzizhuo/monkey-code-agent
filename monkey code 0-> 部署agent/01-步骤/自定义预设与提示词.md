# 自定义 Agent：预设与提示词

一条快捷路径：**只改一个 JSON 文件**。不需要读源码，不需要重建镜像。

---

## 三步走

### 第 1 步：创建配置文件

```bash
cd /workspace
cp .isolis/isolis.config.example.json .isolis/isolis.config.json
```

`isolis.config.example.json` 就是完整模板，字段全部有默认值，删掉哪个字段就用内置默认。

### 第 2 步：改它

最小可用示例：

```json
{
  "default_profile": "tooled",
  "prompt": "你是一个严谨的 Python 工程师。回答前先跑测试。",
  "profiles": {
    "tooled": { "memory": "8g", "cpus": "4.0", "pids": "1024" }
  }
}
```

### 第 3 步：生效

```bash
python3 isolis.py stop
python3 isolis.py init
```

`stop` + `init` 即可。**只有改了镜像内容才需要 rebuild**（见文末判定表）。

验证：

```bash
python3 isolis.py profiles    # 看到 * 标记和 prompt 字符数
python3 isolis.py doctor      # 末尾显示 config 路径与摘要
```

## 完整字段表

### 顶层

| 字段 | 类型 | 作用 | 默认 |
|---|---|---|---|
| `default_profile` | string | `init` 未指定 `--profile` 时用哪个 | `tooled` |
| `model` | string | 覆盖模型选择 | 空（走原优先级） |
| `prompt` | string | 直接写提示词正文 | 空（用内置） |
| `prompt_file` | string | 从文件读提示词（相对 `/workspace`） | 空 |
| `profiles` | object | 覆盖或新增 profile | `{}` |

`prompt` 与 `prompt_file` 同时存在时，**`prompt_file` 优先**。两者都空则用内置提示词。

### `profiles.<name>` 可覆盖的字段

| 字段 | 类型 | 作用 | 示例 |
|---|---|---|---|
| `memory` | string | 内存上限 | `"8g"` |
| `cpus` | string | CPU 核数 | `"4.0"` |
| `pids` | string | 进程数上限 | `"1024"` |
| `workspace` | string | `/work` tmpfs 大小 | `"4g"` |
| `tmp` | string | `/tmp` tmpfs 大小 | `"1g"` |
| `shm` | string | `/dev/shm` 大小 | `"512m"` |
| `user` | string | 容器内用户 | `"0:0"` 或 `"nobody"` |
| `caps` | list | 附加 capabilities | `["CHOWN","FOWNER"]` |
| `read_only` | bool | 根文件系统只读 | `true` / `false` |
| `install` | bool | 是否开放装包工具 | `true` / `false` |

**合并语义**：配置文件里的字段覆盖内置值，未写的字段保留内置值。
所以 `{"profiles":{"tooled":{"memory":"8g"}}}` 只改内存，其他不变。

**新增 profile**：用任意新名字，未写的字段继承 `tooled` 的基线。

```json
{
  "profiles": {
    "data": {
      "memory": "2g", "cpus": "2.0", "pids": "256",
      "read_only": true, "install": false, "user": "nobody", "caps": []
    }
  }
}
```

然后 `python3 isolis.py init --profile data`。

## 提示词怎么写

### 方式 A：内联（短提示词）

```json
{ "prompt": "你是 Go 专家。优先写表驱动测试。回答用中文。" }
```

### 方式 B：独立文件（长提示词，推荐）

配置里写相对路径，相对于 `/workspace`：

```json
{ "prompt_file": "agent-prompt.md" }
```

`/workspace/agent-prompt.md` 就是提示词正文，随便写多行：

```markdown
You are Isolis, a coding agent inside an isolated Docker container.
Workspace is /work.

Rules:
- Match the user's language.
- Verify by running commands; never claim success without output.
- Prefer small, reviewable diffs.
```

改完文件同样 `stop` + `init`，**不用重建镜像**——提示词是运行时通过
`ISOLIS_SYSTEM_PROMPT` 环境变量注入容器的。

### 提示词和工具的关系

内置提示词会追加一句「你的 profile 是什么、能不能装包」。你自定义的提示词
会**完全替换**内置内容，那句自动追加也不会出现。如果自定义提示词需要提及
工具能力，自己在正文里写清楚。

## 优先级规则

```
环境变量  >  配置文件  >  内置默认
```

具体：

- `ISOLIS_PROFILE` 覆盖 `default_profile`
- 命令行 `--profile` 覆盖 `ISOLIS_PROFILE`
- `ISOLIS_MODEL` 覆盖配置里的 `model`
- 命令行 `--model` 设置 `ISOLIS_MODEL`，因此最高

这意味着临时试一次可以不改文件：

```bash
ISOLIS_PROFILE=strict python3 isolis.py init
```

## 改了要做什么

| 你改了什么 | 需要执行 | 原因 |
|---|---|---|
| `profiles` 里的数值 | `stop` + `init` | profile 只影响 `docker run` 参数 |
| `prompt` / `prompt_file` | `stop` + `init` | 通过环境变量注入 |
| `default_profile` | `stop` + `init` | 同上 |
| `model` | `stop` + `init` | 通过环境变量注入 |
| `agent/Dockerfile` | `rebuild` | 镜像内容变了 |
| `agent/server.py` | `rebuild` | `COPY` 进镜像 |
| `agent/requirements.txt` | `rebuild` | 同上 |
| `agent/install-android-sdk.sh` | `rebuild` | 同上 |

判定原则：**配置文件里的一切都是运行时注入，改完 `stop`+`init`；
`agent/` 目录下的一切都是构建时烘焙，改完要 `rebuild`。**

## 常见自定义场景

### 场景 1：给它更多内存做 Android 构建

```json
{ "profiles": { "tooled": { "memory": "12g", "cpus": "6.0", "workspace": "8g" } } }
```

### 场景 2：只读分析档，禁止任何写操作

```json
{
  "profiles": {
    "audit": {
      "read_only": true, "install": false,
      "user": "nobody", "caps": [],
      "memory": "1g", "cpus": "1.0", "pids": "128"
    }
  },
  "default_profile": "audit"
}
```

### 场景 3：换成专注代码审查的 agent

配置：

```json
{ "prompt_file": "reviewer.md", "profiles": { "tooled": { "install": false } } }
```

`/workspace/reviewer.md`：

```markdown
You are a code reviewer. Read code, run linters and tests, report findings.
Never rewrite files unless explicitly asked. Cite file:line for every finding.
Group findings by severity: blocker, major, minor.
```

### 场景 4：多套人设随时切换

建多个提示词文件，靠改一行配置切换：

```bash
# 切到 reviewer
python3 - <<'PY'
import json
p = ".isolis/isolis.config.json"
cfg = json.load(open(p))
cfg["prompt_file"] = "reviewer.md"
json.dump(cfg, open(p, "w"), indent=2)
PY
python3 isolis.py stop && python3 isolis.py init
```

## 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `unknown keys: xxx` | profile 里写了不存在的字段 | 对照字段表，注意拼写 |
| `must be a list` / `must be true or false` | 类型错 | `caps` 是数组，`read_only`/`install` 是布尔 |
| `cannot read prompt_file` | 路径不存在 | 相对路径基于 `/workspace` |
| 改了配置没变化 | 没重建容器 | `stop` + `init` |
| `profiles` 里有 `*` 但值没变 | 字段名拼错，被当成未知字段 | 会直接报错，看错误信息 |
| 提示词里有中文乱码 | 文件编码 | 存成 UTF-8 |

配置写错时 `isolis.py` 会**直接报错并拒绝启动**，不会静默使用错误配置。
这是刻意的：宁可启动失败，也不要跑在一个你以为改了但实际没改的环境里。

## 文件位置

| 文件 | 说明 |
|---|---|
| `/workspace/.isolis/isolis.config.json` | 你的实际配置（已被 gitignore） |
| `/workspace/.isolis/isolis.config.example.json` | 完整模板，可随时对照 |
| `/workspace/agent-prompt.md` | 提示词文件示例 |

`.isolis/` 整个目录在 `.gitignore` 里，你的自定义配置不会被提交，
也不会影响别人 clone 后的默认行为。
