# 示例环境：按当前状态逐步引导

本文以**归档时刻真实运行的环境**为准，带你从零开始走一遍：
看环境、认状态、发指令、验证隔离、读懂返回。
每一步都给出命令与当时的真实输出，你可以逐条对照。

`实测输出/` 目录保存了这些输出的原始抓取，可随时 `bash capture.sh` 刷新。

---

## 你现在面对的是什么

一个宿主进程 `isolis.py` 通过 Docker 启动了一个隔离容器，容器里跑着
`agent/server.py`，对外只暴露一个 loopback 端口。你和容器唯一的交互入口是
`isolis>` 这个 TUI。

```
你的终端 (isolis TUI)
   │  python3 isolis.py
   ▼
宿主 orchestrator (isolis.py)  ── Docker CLI ──►  isolis-default 容器
   │                                              agent/server.py :8080
   │  HTTP 127.0.0.1:18080                        LangChain + 工具 + 记忆
   ▼
MonkeyCode 网关 (proxy.monkeycode-ai.com)  ◄── 容器内 LLM 调用
```

当前实例的关键事实：

| 项 | 值 |
|---|---|
| 容器名 | `isolis-default` |
| 镜像 | `isolis-agent:tooled-ca22788ffe` |
| 端口 | `127.0.0.1:18080 -> 8080` |
| profile | `tooled`（可写根、root、可装包） |
| 模型 | `monkeycode-basic/deepseek-flash` |
| 协议 | `anthropic`（网关探测结果） |
| 工具数 | 7 |
| 网络 | `isolis-net`，icc off |

## 第一步：确认 Docker 活着

```bash
docker --version
docker info --format '{{.ServerVersion}} driver={{.Driver}}'
```

真实输出：

```
Docker version 20.10.24+dfsg1, build 297e128
20.10.24+dfsg1 driver=overlay2
```

如果 `docker info` 报连不上 socket，说明 daemon 没起。按
`01-步骤/完整步骤.md` 阶段 6 启动它（用后台终端，不要用 `&`）。

## 第二步：让 isolis 自检

```bash
cd /workspace
python3 isolis.py doctor
```

真实输出（注意那条 `[fail]`）：

```
isolis doctor
  [ok]   Docker version 20.10.24+dfsg1, build 297e128
  [ok]   daemon reachable
  [ok]   Docker Hub blocked, mirror configured: https://docker.m.daocloud.io
  [fail] MonkeyCode LLM was not injected: MCAI_LLM_BASE_URL and MCAI_LLM_API_KEY are required
  [ok]   agent sources: /workspace/agent
  [ok]   profile: tooled (install on)
  [ok]   context budget: 900000 tokens of 1000000 upstream max (auto compression on)
  [ok]   limits: turns 400, message 900000 chars
  [ok]   agent source: local (/workspace/agent)
  [ok]   image isolis-agent:tooled-ca22788ffe present
  [ok]   network isolis-net present
  [ok]   state file readable (1 agents, current: default)
result: not ready (fix the [fail] lines)
```

**这条 fail 是预期的**，原因如下：

- `MCAI_LLM_*` 只注入你的 TUI 会话，不注入我执行命令的 shell。
- 我在这里跑 `doctor` 时拿不到 Key，所以必然报 fail。
- 你在自己的 `isolis>` 会话里跑，这一行会是 `[ok]`。

判断标准：**除 LLM 那一行外全 ok，就说明环境是对的**。

## 第三步：看 profile

```bash
python3 isolis.py profiles
```

真实输出：

```
capability profiles:
  strict   install off memory 512m cpus 1.0 pids 128  user nobody
  tooled   install on  memory 4g   cpus 2.0 pids 512  user 0:0
default: tooled
```

两个档位的取舍：

| | strict | tooled |
|---|---|---|
| 根文件系统 | 只读 | 可写 |
| 用户 | `nobody` | `0:0` |
| 装包 | 拒绝 | 允许 |
| 内存 / CPU / pids | 512m / 1 / 128 | 4g / 2 / 512 |
| 适用 | 只读分析、跑现成代码 | 真实编译、装 SDK、构建 APK |

默认 tooled，因为 Isolis 的目标是「真实开发能力」。
需要强隔离时切 strict。

## 第四步：看当前状态

```bash
python3 isolis.py status
```

真实输出：

```
* default              running  127.0.0.1:18080  tooled     monkeycode-basic/deepseek-flash
isolation[tooled]: root writable, tmpfs /tmp 512m, workspace /work 2g, pids 512, memory 4g, cpus 2.0, user 0:0, cap-drop ALL, caps CHOWN,DAC_OVERRIDE,FOWNER,SETUID,SETGID,SETFCAP, no-new-privileges, install on, no host mounts, no docker socket
```

## 第五步：验证隔离（最重要）

不信任 `status` 的自述，直接问 Docker：

```bash
docker inspect isolis-default --format \
  'User={{.Config.User}} RO={{.HostConfig.ReadonlyRootfs}} \
CapDrop={{.HostConfig.CapDrop}} CapAdd={{.HostConfig.CapAdd}} \
Mem={{.HostConfig.Memory}} NanoCpus={{.HostConfig.NanoCpus}} \
Pids={{.HostConfig.PidsLimit}} Ports={{.HostConfig.PortBindings}} \
Mounts={{len .Mounts}} Net={{.HostConfig.NetworkMode}}'
```

真实输出：

```
User=0:0 RO=false CapDrop=[ALL] CapAdd=[CHOWN DAC_OVERRIDE FOWNER SETUID SETGID SETFCAP] Mem=4294967296 NanoCpus=2000000000 Pids=512 Ports=map[8080/tcp:[map[HostIp:127.0.0.1 HostPort:18080]]] Mounts=0 Net=isolis-net
```

逐项解读：

| 字段 | 值 | 含义 |
|---|---|---|
| `User=0:0` | root | tooled 档允许装包，需要 root |
| `RO=false` | 可写 | 同上 |
| `CapDrop=[ALL]` | 全丢 | 先清空能力，再加白名单 |
| `CapAdd` | 6 项 | CHOWN/DAC_OVERRIDE/FOWNER/SETUID/SETGID/SETFCAP |
| `Mem=4294967296` | 4 GiB | 内存硬上限 |
| `NanoCpus=2000000000` | 2 核 | CPU 上限 |
| `Pids=512` | 512 | fork 炸弹防护 |
| `Ports` | 单个 127.0.0.1 | 只在 loopback 暴露 |
| `Mounts=0` | 无 | **没有挂载宿主目录** |
| `Net=isolis-net` | 专用网 | icc off，容器间不互通 |

两个红线必须确认：

```bash
# 不能有宿主目录挂载
docker inspect isolis-default --format '{{range .Mounts}}{{.Source}}->{{.Destination}}{{end}}'
# 期望：空

# 不能挂 docker.sock
docker inspect isolis-default --format '{{range .Mounts}}{{.Source}}{{end}}' | grep -c docker.sock
# 期望：0
```

## 第六步：和容器对话（HTTP 层）

宿主 TUI 走的是同一组接口。你可以直接用 curl 看契约。

### 健康检查

```bash
curl -sS http://127.0.0.1:18080/health | python3 -m json.tool
```

```json
{
    "ok": true,
    "agent": "default",
    "hostname": "300e6f505854",
    "pid": 7,
    "cwd": "/app"
}
```

`hostname` 和 `pid` 是容器内部身份，证明响应来自容器而非宿主。

### 对话历史

```bash
curl -sS http://127.0.0.1:18080/history | python3 -m json.tool
```

```json
{
    "ok": true,
    "context_tokens": 900000,
    "history_tokens": 38,
```

## 第七步：在 TUI 里实际操作

以上都是只读观察。真正的交互在 `isolis>` 里：

```bash
cd /workspace
python3 isolis.py
```

进入后输入 `help` 看命令，然后：

```
isolis> init
isolis> status
isolis> chat
```

`chat` 进入对话模式：

```
you> 在当前目录写一个 hello.py 并运行
```

agent 会调用 `write_file` + `run_command`，返回运行结果。

两个特殊输入：

- `/back`：退出对话，回到 `isolis>`
- `/quit`：直接退出 TUI

### 一次完整的开发会话示例

```
you> 建一个目录 demo，写一个读取 /work 下所有文件的 Python 脚本并运行
```

agent 的动作序列（可在 `history` 里核对）：

1. `run_command` → `mkdir -p /work/demo`
2. `write_file` → `/work/demo/list.py`
3. `run_command` → `python3 /work/demo/list.py`
4. 返回 stdout 给你

这就是「真实开发能力」的最小闭环：写文件、执行、拿到真实输出。

## 第八步：验证工具链真的在镜像里

不进 TUI 也能验证。直接跑一次性容器：

```bash
docker run --rm --network none isolis-agent:tooled-ca22788ffe sh -c '
  echo "--- java ---";        java -version 2>&1 | head -1
  echo "--- node ---";        node -v
  echo "--- python ---";      python3 -V
  echo "--- langchain ---";   python3 -c "import langchain_core; print(langchain_core.__version__)"
  echo "--- playwright ---";  python3 -c "import playwright; print(\"ok\")"
  echo "--- build ---";       cmake --version | head -1; gcc --version | head -1
  echo "--- cli ---";         git --version; rg --version | head -1; jq --version
'
```

期望全部有版本号输出。任何一项缺失说明镜像构建不完整。

## 第九步：理解数据存哪

| 数据 | 位置 | 生命周期 |
|---|---|---|
| 运行状态 | `/workspace/.isolis/state.json` | 持久，原子写 |
| agent 源码 clone | `/workspace/.isolis/agent-src/` | 持久，`git-url` 源时才有 |
| 容器内工作区 | `/work`（tmpfs） | **容器停就没了** |
| 容器内临时目录 | `/tmp`（tmpfs） | 同上 |
| 容器内缓存 | `/tmp` 下各工具缓存 | 同上 |

`/work` 是 tmpfs 是刻意的取舍：换一个干净的隔离环境，代价是重启丢失。
如果需要保留产物，在会话结束前用 `read_file` 取回内容，或写到宿主的其他位置。

## 第十步：常见操作

### 切换到 strict 档

```bash
python3 isolis.py stop
python3 isolis.py init --profile strict
python3 isolis.py status
```

`status` 会显示 `isolation[strict]: root readonly, ... user nobody, no caps, install off`。
此后装包类工具会明确拒绝。

### 用指定模型

```bash
python3 isolis.py rebuild --model monkeycode-pro/gpt-5.6-terra
```

模型优先级：`ISOLIS_MODEL` > `MCAI_LLM_MODEL` > 平台前缀首个 > `ISOLIS_DEFAULT_MODEL` > 内置。

### 换 agent 源码

```bash
python3 isolis.py stop
python3 isolis.py init --source https://your-git/repo.git
```

会 clone 到 `.isolis/agent-src/`，并用不同的镜像 tag 区分。

### 停止与清理

```bash
python3 isolis.py stop          # 停止并删除容器
python3 isolis.py status        # 确认已无运行实例
```

## 一次完整的自检脚本

把前九步串起来，一条命令跑完：

```bash
cd /workspace

echo "== doctor =="
python3 isolis.py doctor || true

echo "== isolation =="

  'user={{.Config.User}} ro={{.HostConfig.ReadonlyRootfs}} caps_add={{.HostConfig.CapAdd}} mounts={{len .Mounts}}'

echo "== http =="
curl -sS http://127.0.0.1:18080/health  | python3 -m json.tool
curl -sS http://127.0.0.1:18080/info    | python3 -c 'import json,sys;d=json.load(sys.stdin);print({k:d[k] for k in ("profile","model","protocol","injected","tools")})'
```

## 读懂报错

| 报错 | 含义 | 处理 |
|---|---|---|
| `docker CLI not found` | 没装 Docker | `apt-get install -y docker.io` |
| `docker daemon` 连不上 | dockerd 没起 | 后台终端启动 dockerd |
| `LLM was not injected` | 当前 shell 无 `MCAI_LLM_*` | 用 TUI 会话跑，这是设计行为 |
| `image ... not present` | 镜像没构建 | `python3 isolis.py setup` |
| `port ... exhausted` | 18080-18119 全占用 | 清理闲置容器 |
| strict 下 `install_packages` 被拒 | profile 限制 | 换 tooled 档 |
